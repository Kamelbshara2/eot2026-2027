# Assessment and study-booklet production standard

Applies to all future uploaded classes and textbooks for this platform. The latest user instruction permits concept applications and small variations of worked examples. Never label these as verbatim book exercises.

1. Map the supplied coverage to grade, general/advanced track, topic and learning outcome. Record whether each reference is an exercise, worked example, principle or theorem. Keep source book hash, printed page, PDF page, exercise and parent question.
2. Write MCQ stems as complete exam questions. Cover calculation, interpretation, inverse use, conditions, common errors and graph reading where relevant. Each MCQ has four distinct choices and exactly one correct choice. Check algebraic equivalence, not only strings. Distractors should reflect a named plausible mistake; avoid unrelated variables, random ±1 variations and duplicate equivalent answers.
3. For examples and principle references add labelled `example_variant` or `concept_application` questions. Keep their origin distinct from `textbook_exercise`. Balance practice and mock selection by LO. Do not claim predictions of particular final-exam questions.
4. Written exercises retain the book's data and all requested parts. Add working space. Linear graphs get 2–3 table points, quadratics get five including the vertex when suitable. Tables in question areas are blank; completed values and answers belong to solutions. When a graph is the given information, do not reveal its equation in a hint before the student derives it.
5. Current calculator model: **Casio fx-991EX ClassWiz**. Use MENU Calculate, MENU Table, appropriate Degree setting and full precision until final rounding. Distinguish numerical evaluation, equation solving, numeric verification and proof. TABLE produces values, not plotted graphs. Label instructional key diagrams honestly; never represent them as official emulator screenshots. A new calculator model requires rechecking menus.
6. Retain original diagrams as lossless crops. Inspect every crop against the source page for all vertex labels, arrowheads, side lengths, scales and signs. Enlarge the crop/display when needed; never use generative reconstruction to invent missing labels, add answer annotations or insert facts absent from the original question. Preserve the original source alongside audit metadata.
7. Booklets: A4, no more than 30 pages unless the user changes the limit, 4–5 questions per idea, two-column MCQs where readable, full-width for wide options; complete FRQs and generous working areas. Clear hierarchy, restrained colour, strong contrast, embedded fonts, printable original figures. Check page bounds, column overflow, every image and the actual printed key against the current bank.
8. Export a normalized database and JSON grouped by grade/track/LO/type, with separate questions, options, marking keys, parts, media and calculator guides. Include schema, import instructions and asset checksums. For real exams, serve prompts/options only; keep keys and grading server-side. Practice banks may show explanations after the student requests them.
9. Validate the content mathematically and run browser tests of practice, shuffled grading, timer and persistence. A passing software test is not proof of mathematical correctness. Keep source review and artifact consistency as separate checks.

Rebuild: original textbook extraction scripts → `scripts/revise-study-banks.py` → calculator guide renderer → booklet HTML/PDF exporter → database packager. Current baseline inputs are retained under `content-imports/textbook-v1-inputs/`. Do not overwrite newer reviewed questions by running only an older extractor.

## Interactive study booklet (web) — added fill-in-the-blank, calculator and quiz layers

- `lib/study-booklet.js` renders five colour-coded lesson parts: 1 Idea, 2 Worked example, 3 Study helper, 4 Practise, 5 Quiz. Every block carries a label (QUESTION / SOLUTION / HELPER / YOUR ANSWER). Do not merge them again.
- Written (FRQ) parts may carry `blanks` = `{lines:[LaTeX with [[blanks]]], table?:{xs,ys}}`. Syntax and checking rules are in `lib/study-fill.js`. Generate them with `python3 scripts/add-study-blanks.py` (requires `sympy`) **after** the study JSON is rebuilt; the script is idempotent and also applies reviewed corrections. Answers are computed from the stem wherever possible. Blanks must never reveal a value that the student should read from a given graph.
- Parts with no `blanks` (graphs to draw, explanations) stay paper-only with the reference solution.
- Quizzes (`/banks/term1/quiz?lo=…&n=…&mix=…&t=1`) draw round-robin across the chosen outcomes from MCQs and blank-bearing FRQs only. Practice quizzes grade in the browser and may show explanations; a real exam must not use this path (keys are in the public JSON).
- Calculator guides render as selectable text steps + key chips; the PNG is secondary. Questions without a calculator route state why.

## Teacher revision booklet import (10 Advanced)
`scripts/import-g10a-revision.py` (parse) → `scripts/build-g10a-revision-questions.py` (build) → `scripts/add-study-blanks.py` → `scripts/coverage-gap.py` → `scripts/audit-study-questions.py`. Items are matched to the coverage sheet by order and imported only when their (page, exercise) is absent (no duplicates). Imported ids are `G10A-REV-*`; `source.revision_booklet` keeps the file hash, PDF page and question number; `key_source` records how the key was verified (`sympy-verified`, `recomputed-numeric`, `teacher-revision-booklet`). Figures with cut-off labels are held back (see `build-report.json › held_back`), never redrawn.
